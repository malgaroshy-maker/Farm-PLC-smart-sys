# Farm-PLC AI audit

**26 November 2026 · `milestone-g` · reviewed working tree**

The owner chose clear Modern Standard Arabic and a short, practical, direct tone. The live evaluation used labeled, sanitized test fixtures. The repository and application tests covered chat, alarm explanations, irrigation advice, briefings, model configuration, privacy, tool calling, and how responses reach the web UI.

Both configured APInex models produced structured responses and called the history tool during the initial audit. The baseline audit reproduced four application defects with direct effects on operators. Model output could change the scope of an approved weather override. Missing telemetry could appear as zero, a briefing could omit open alarms, and a critical alarm could lose its safety warning. The implementation now addresses these defects in the working tree.

## Remediation and verification

| Area | Change |
|---|---|
| Alarm explanations | The selected alarm record supplies identity, condition and severity. The catalog supplies safety guidance. Follow-up questions reach the model and a missing or uncalibrated diagnosis confidence is omitted. |
| Weather advisor | The server selects the first eligible program by start time and ID, uses that day's verified forecast and enforces the date, program, zones and adjustment on approval. Older suggestions with unverified scope cannot be approved. |
| Readings and briefings | Missing or stale readings retain their status. The recap uses the previous farm-local calendar day. Open alarms are included and incomplete water records are not presented as a complete total. Synthetic offline weather is excluded. |
| Briefing schedule | The existing schedule card reads the current farm day's configured programs and approved one-day overrides from the database. It refreshes even when the narrative is cached. Past dates have no saved program snapshot. |
| Anomaly calibration | Calibration uses paired, measured flow and pressure. Estimated water volume and nominal pressure cannot qualify a cycle for the baseline. |
| Chat and tools | The assistant receives the farm-local date, observed data and controller capability facts. History tools accept configured zone names and codes. A direct question about yesterday's water volume for one identified zone can be answered from stored cycles, with estimates and the simulation environment labeled. A bilingual label under each sourced answer names the records that supplied evidence. The browser sends the operator's question without appended telemetry substitutes. |
| Arabic and English | Operator responses favor direct Modern Standard Arabic and short answers. The chat returns the requested language and gives a local answer when a model produces unusable Arabic. Alarm wording distinguishes acknowledgment from uncertainty about the cause. The Arabic validator accepts product names such as PLCSIM Advanced and WinCC Unified and reads the current zone codes from the database. |
| Providers and diagnostics | The runner uses configured provider order, overall deadlines and bounded requests. It records the provider and model that answered. Credential-bearing requests use deployment-approved HTTPS destinations and connection tests exercise structured output. |

Post-repair checks used a separate in-memory database and sanitized live prompts. DeepSeek V4 Pro answered the S3 alarm follow-up, and the server retained the catalog safety warning. The equivalent history request returned the fixture's estimated 0.73 m³ from the cycle records. A live briefing added model synthesis while server-owned fields retained the open alarm, estimated volume and unavailable forecast. The advisor used its local rule after a model response failed Arabic validation. The full API suite passed 262 tests, including the briefing schedule at Tripoli midnight and an approved skip applied to a cached briefing. The web suite passed 110 tests, including source labels in both languages. TypeScript and lint checks passed for the changes.

## Findings and repair priorities

### P1 · Safety, operator decisions, and factual data

1. **A model can change the date and program of an approved weather override — Reproduced.** Rules overwrite the action, duration factor and zone list. The service still stores the model's `target_date` and `program_id`. In the isolated probe, the server selected `2026-01-10` and `test-program`. The approved override used `2026-01-11` and a null program ID. The scheduler treats a null program as a match for any eligible program and consumes the override on use. Construct the full executable payload on the server, let the model return explanatory text only, and validate scope and expiration at approval. The current UI's list of affected zones can also span programs while the override applies to one program. [Advisor persistence](../apps/api/app/services/ai/advisor.py#L127) · [Scheduler matching](../apps/api/app/services/scheduler.py#L447)
2. **Critical alarm warnings are unreliable — Reproduced.** The rule-based explanation for ALM-005 returned `severity=S3` with `safety_critical=false`. Its Arabic output also rendered missing threshold values as `None`. The web client uses the safety flag to supply the warning. A remote model can choose severity and the flag in the output schema. Both live alarm samples returned `major` in that field. Derive severity, safety flags, and official guidance from the alarm catalog and live record. Let the model explain evidence and uncertainty. [Catalog severity](../apps/api/app/core/alarm_catalog.py#L6) · [Offline alarm explanation](../apps/api/app/services/ai/rules.py#L23) · [Alarm UI mapping](../apps/web/src/lib/api.ts#L325)
3. **Missing and stale records can become confident measurements — Reproduced.** A configured zone without a snapshot returned `idle`, `0.0` flow, `0.0` pressure and `valve_open=false`, with no timestamp. Cycle history returned `0.0` for missing volume and dropped `water_is_estimate` for a cycle with recorded estimated volume. The rolling history tool also lacks a farm-local date range and caps responses without indicating truncation, so totals for “yesterday” can be misleading. Preserve nulls, observed timestamps, freshness, measured or estimated provenance, and completeness. Use Tripoli-date ranges for calendar totals. [Zone and history tools](../apps/api/app/services/ai/tools.py#L94)
4. **A briefing can report normal conditions during an open critical alarm — Reproduced.** The engine uses `active_unacked` and `active_acked`. The briefing query and fallback check `active`. The probe supplied an open S3 alarm and received “All systems normal. No active alarms.” Briefing collection also uses the past 24 hours even when the requested date is different. Use canonical alarm states and authoritative date-specific aggregates. Supply those facts directly to the renderer and ask the model only for synthesis. [Alarm states](../apps/api/app/services/alarms.py#L43) · [Briefing query](../apps/api/app/services/ai/briefing.py#L29) · [Offline briefing](../apps/api/app/services/ai/rules.py#L260)
5. **Alarm explanations can be reused for the wrong zone — Reproduced.** Two ALM-013 requests for different zones with the same reading reused one model result. The cache key uses code, language and reading. It omits alarm identity, zone, status, threshold and snapshot version. Key the cache by the evidence used for the explanation, or limit it to static catalog guidance. [Alarm cache key](../apps/api/app/services/ai/agent.py#L644)
6. **Outbound scope and redaction need a stronger boundary — Code review.** The chat prompt serializes conversation history and the live farm snapshot. The regex masks common patterns and some fixed Latin names. A probe showed it also removes the role word `operator`. Tool results and returned exception messages have no equivalent structured redaction step. The admin-saved provider URL is a plain string that the primary model constructor pairs with the configured provider credential. Restrict destinations to approved HTTPS endpoints, send only fields needed for the feature, redact tool returns and diagnostics, and keep free-text operational fields out of provider payloads by default. The sanitized live run excluded these inputs. [Redactor](../apps/api/app/services/ai/redaction.py) · [Tool returns](../apps/api/app/services/ai/tools.py#L47) · [Provider settings](../apps/api/app/routers/ai.py#L499) · [Provider construction](../apps/api/app/services/ai/providers.py#L75)
7. **Synthetic weather can reach the assistant as a forecast — Reproduced.** With the provider and caches unavailable, the weather service constructed clear-sky weather and labeled it `offline_fallback`. The forecast tool returned a daily high of 31 °C without that label or a timestamp. The advisor and briefing consume weather figures with no corresponding provenance gate. Return an explicit unavailable state for operational advice and briefings. Keep test weather behind a labeled simulator path. [Weather fallback](../apps/api/app/services/weather.py#L152) · [Forecast tool](../apps/api/app/services/ai/tools.py#L312)
8. **Anomaly calibration can use unmeasured pressure — Reproduced.** With three estimated-volume cycles and no telemetry, the service built a baseline using 4.2 m³/h from estimated volume and 3.0 bar from the configured band midpoint. A zone can appear calibrated before paired measurements exist. Use measured paired cycles for calibration, record provenance and counts, and keep inferred data separate in the baseline UI. The deterministic soil tests passed, including the approved extra-run path through normal command interlocks. [Anomaly calibration](../apps/api/app/services/anomaly.py#L170) · [Soil test coverage](../apps/api/tests/test_g7_soil.py#L87)

### P2 · Conversation, language, tools, and reliability

9. **Alarm follow-up questions are discarded — Code review.** The drawer sends a `question` field and renders the response as an answer. The API schema omits that field and the route calls the initial explanation again. The drawer's general-chat fallback triggers only on request error. Use a contextual follow-up route or accept and handle the question in the existing contract. Test the meaning of the returned answer, including a second question about a different part of the fault. [Drawer](../apps/web/src/components/ai/ExplainAlarmDrawer.tsx#L195) · [API contract](../apps/api/app/services/ai/schemas.py#L76) · [Route](../apps/api/app/routers/ai.py#L124)
10. **Offline chat can give a false all-clear or outdated farm details — Reproduced and code review.** No schedule information became “No irrigation is scheduled in the next 24 hours.” A stale alarm count returned “There are no active alarms” without a freshness caveat. The generic zone reply hard-codes a 12-zone inventory, while the live path builds inventory from the database. Fallback facts are stored in process-global `LAST_FACTS`. Pass a request-local snapshot and give the fallback explicit unavailable, stale, empty and observed states. [Snapshot builder](../apps/api/app/services/ai/live_context.py#L35) · [Offline chat](../apps/api/app/services/ai/rules.py#L302) · [Chat pipeline](../apps/api/app/services/ai/agent.py#L843)
11. **Arabic purity checks do not guarantee usable Arabic — Live evidence and code review.** The prompt already requires Modern Standard Arabic. The guard looks for foreign script and Latin words in Arabic fields. It accepts empty Arabic fields and ignores the optional generic `message`, which the web client prioritizes. It checks Arabic even for English requests, so MiniMax's faulty secondary field can delay a good English answer. It can also accept a second reply with remaining violations if it improves on the first. Validate and render the requested language field, enforce nonempty operator-facing text, preserve legitimate codes and units, and measure human readability independently. [Prompt glossary](../apps/api/app/services/ai/live_context.py#L22) · [Purity guard](../apps/api/app/services/ai/purity.py#L147) · [Retry rules](../apps/api/app/services/ai/agent.py#L493) · [Chat rendering](../apps/web/src/lib/api.ts#L358)
12. **Tool routing is useful but too dependent on model judgment — Code review and live evidence.** Only the model's fast-pass `needs_history` triggers tool chat. The six tools are read-only, with independent database sessions. This is a sound boundary. The same tool set is exposed to all tool-enabled features, and chat history accepts arbitrary role strings. The UI drops the returned chat references. Add explicit routing for history and alarm detail, limit the available tools by feature, constrain roles and input sizes, and construct references from successful tool results. Handle unsupported tools and empty records explicitly. [Tool definitions](../apps/api/app/services/ai/tools.py) · [Agent setup](../apps/api/app/services/ai/agent.py#L373) · [Chat input schema](../apps/api/app/services/ai/schemas.py#L82) · [Web client](../apps/web/src/lib/api.ts#L335)
13. **Settings and diagnostics can disagree with the real fallback path — Code review.** The built chain attempts configured model objects even when a credential is absent. The provider order, token budget, and offline fallback preferences presented in settings are not enforced by the main runner. Timeout applies per run and can be repeated by fallback and Arabic cleanup. Successful local and cross-model fallback can be lost in attribution. Some purity fallback branches return before call logging. The connection test checks an unstructured reply and uses environment provider construction independently of the stored primary base URL. Use a single resolved settings object, an overall time and request budget, a secret-safe attempt record, and production-shaped health checks. [Provider chain](../apps/api/app/services/ai/providers.py#L115) · [Runner](../apps/api/app/services/ai/agent.py#L434) · [Connection test](../apps/api/app/routers/ai.py#L582)

## Language, tone, and knowledge of Farm-PLC

- Use direct Modern Standard Arabic even when the question is in Libyan Arabic. Use the existing glossary for `مضخة التعزيز` and `صمام`. Say `إنذار حرج` for S3 and `إنذار من الدرجة الثانية` or the approved product term for S2. Use natural number phrasing such as `اكتملت دورتان` and keep stable technical codes such as ALM-013.
- Lead with the answer. Use one or two short sentences for a reading or status. Add one concrete next action when the operator needs it. Put freshness beside the measurement. For an alarm, give the observed condition, the probable cause with its uncertainty, and the next safe check. Keep internal IDs out of prose when a display name is available.
- Example for stale data: «آخر قراءة للضغط الرئيسي 2.30 بار، وقد تكون قديمة. قراءة رطوبة التربة غير متاحة.»
- Example for a possible leak: «أوقف المتحكم الري بسبب ارتفاع التدفق. افحص الخط والصمام في الموقع قبل إعادة التشغيل.»
- The live prompts include zones, crops, state, representative telemetry, active alarms and the next run. They lack a curated, versioned source for project-specific questions about controller modes, simulated versus field readings, PLC versus app alarm responsibilities, or current HMI capabilities. The models got the project-boundary case right when those facts were supplied. Add a small read-only capability summary drawn from authoritative configuration and verified project status. Attach source and freshness metadata to responses where it changes the answer. [Live context](../apps/api/app/services/ai/live_context.py) · [Verified project status](../PROJECT_STATUS.md)
